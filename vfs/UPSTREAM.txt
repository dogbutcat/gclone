Purpose: document the temporary, repository-local VFS override in gclone.

SOURCE
  Synced with rclone v1.75.2, commit be8d6044eacb843b74d335db0c5fbe09222031fe.
  VFS lifetime fix originally prepared at ef2553b129df9bad7393513a3e2297e29895e2cf
  against v1.75.1 and retained during this upgrade. Official v1.75.2 still
  reproduces the unlink/writeback defect in all 8 Linux FUSE regression cases.
  No additional remote fork or module replacement is required.
  go.mod continues to depend on the official github.com/rclone/rclone module.
  UPSTREAM.json records every copied file, original hash and import mapping.
  Headers on unchanged files retain their first-copy version; UPSTREAM.json
  identifies the current synchronized upstream base for every copied file.
  Preserve the upstream MIT license in COPYING.rclone beside these notes.

LOCAL OVERRIDE
  vfs/** supplies the VFS, cache, options, flags and regression tests.
  cmd/{mountlib,mount,mount2,cmount,nfsmount} use this local VFS.
  VFS-backed serve commands and their proxy share the same VFS/options.
  backend/archive with squashfs/zip also imports VFS and must use this copy.
  cmd/upstreamselfupdate preserves the original selfupdate command with local
  cmount detection; cmd/selfupdate remains gclone's existing gselfupdate.
  VFS-free serve/restic, serve root, archive CLI and other backends stay upstream.
  Tests use gclone's backend registration. servetest resolves uncopied backend
  test packages through Go instead of a relative source-tree directory.
  fstest/testserver/init.d/README.gclone supplies the directory expected by
  upstream local/configured-remote tests; it does not start external servers.
  Archive CLI tests require a matching rclone executable in PATH; for gclone
  validation use a temporary rclone-named link to the freshly built gclone.

WHY THE ADAPTERS ARE INCLUDED
  Copying vfs alone does not redirect Go imports in upstream commands.
  Two VFS implementations would register the same RC paths and global options;
  registration silently overwrites, so a successful build cannot prove wiring.
  Check go list -deps for both normal and cmount builds on each target platform:
  there must be no github.com/rclone/rclone/vfs or its subpackages in the binary.

FUNCTIONAL FIX
  Explicit unlink retires the File/Item lifetime, drains pending uploads, keeps
  old cached descriptors isolated from same-name replacements, and prevents
  late callbacks from publishing deleted directory entries.
  Remote deletion failure restores cached data and writeback. Rollback failure
  rejects further writes while retaining recovery data. Per-path reservations
  exclude conflicting rename/unlink operations without serializing all files.
  See TestUnlink*, TestCacheUnlink*, TestItemStoreMissingCacheDoesNotPublish.

  mod1.6.5 also retires the old destination during rename-overwrite. In
  upstream v1.75.2, a held clean reader can close after replacement and write
  its old sidecar and mtime into the new cache pathname. The previous unlink
  patch did not cover that rename boundary. Rename now shares the staged
  lifetime transaction, including upload draining and pre-commit rollback.
  Old target handles keep cached bytes but lose namespace/metadata authority.
  Grace closes are fenced during both transitional and terminal retirement.
  Cached and uncached sources, deferred opens and deferred Minimal-mode
  renames use the same destination retirement boundary.

  A remote-committed/local-cache failure advances the committed namespace but
  returns an error. Source cache data is quarantined in the existing recovery
  stage, and affected source handles fail writes rather than acknowledging
  data that cannot upload. Unsafe local rollback also preserves both cached
  generations for recovery rather than restoring the target over the source.
  If quarantine itself fails, a Recovery sidecar marker fences reload; any
  failure to persist that marker is reported and needs manual intervention
  before restart. No cloud-backend atomic rename guarantee is added here.
  See TestRename*, TestCacheRename*, rename_lifetime.go, rename_recovery.go.

  Rename-overwrite waits for ordinary destination open/close operations rather
  than exporting lifecycle-lock contention as EBUSY. Source and target locks
  are acquired in inode order before cache reservations; path bindings are
  revalidated after waiting and locks remain held through publication. The
  destination binding is replaced under one directory lock so lookup cannot
  observe a deletion gap. Retirement and recovery still isolate old handles.
  Overlapping cache reservations expose a completion signal: rename drops
  file locks before waiting, retries resolved pathnames, and keeps its own
  reservation through directory publication. Recovery failures still return
  errors. Revalidation uses resolved names, including case/Unicode aliases.
  It also resolves the caller's original names again while locked: a node
  that moved between lookup and its Name snapshot cannot redirect the call
  to that node's new pathname. Deferred prerequisites trigger a final source
  and destination binding check before any new move or retirement.
  Keep TestRenameOverRevalidatingReader and rename_lock_test.go when dropping
  this local coordination after an upstream implementation passes them.

  mod1.6.6 fences upload/listing object views. A directory snapshot begun
  before a local publication cannot overwrite or remove that newer File.
  The fence uses local publication time, never remote mtime ordering, and
  covers ordinary and recursive listing application. Cache open confirms a
  conflicting clean snapshot with backend NewObject before invalidating data;
  refresh errors preserve the cache. Matching snapshots outside publication
  keep the local fast path; genuine external changes remain visible.
  A resolved cache object is reconciled into its File only if that File's
  object revision has not changed, after releasing all Item locks. Read-only
  reconciliation does not advance the local-publication timestamp.
  Opens during the upload callback revalidate even matching fingerprints:
  a same-content replacement can have a different backend ID. An older File
  snapshot cannot replace the upload result, while a confirmed replacement
  remains the next writeback target. Dirty local bytes remain available.
  Cache opens carry explicit creation intent from O_CREATE and VFS ReadOnly.
  Confirmed clean deletion without that intent returns ENOENT before changing
  cached data or publishing a nil File object. Repeated deferred reads fail
  consistently; normal directory refresh can remove the old directory entry.
  Allowed creation marks the item dirty even without Write, drains any old
  callback first, and retains existing dirty bytes rather than truncating them.
  See upload_consistency_test.go, object_view_test.go, deleted_open_test.go,
  publication_open_test.go and vfscache/{object_view,publication_revalidation}_test.go.
  Drop these guards only with passing upstream upload/listing, external-target,
  creation-intent, unlink and rename lifetime regressions.

  Confirmed absence remains an Item-owned revalidation requirement after the
  callback ends, including matching fingerprints and other deferred handles.
  Observation serials fence destructive invalidation and acceptance across
  writeback/downloader/cache-map unlocks. Ordinary matching opens retain the
  accepted object identity; equal metadata cannot restore an older backend ID.
  Explicit creation commits inside Item after descriptor creation and upload
  draining. Reset and legacy cache opens cannot discharge creation ownership.

  Writeback destination and missing original ranges are separate obligations.
  A vanished or changed source cannot supply uncached bytes: reads/writeback
  fail while retaining dirty data. Failed close tears down unused descriptors
  so reopening can recover. A fresh original-source fingerprint or explicit
  writes can restore the missing data. Destination metadata refresh cannot
  rewrite that saved source fingerprint. Existing recovery of an already-written
  local tail beyond a surviving remote's EOF remains supported.
  Cached reads do not schedule prefetch from an unavailable original source.
  Source replacement drains downloaders, and downloader writers carry a
  separate epoch so late callbacks remain invalid after the source guard clears.
  Closed downloader groups reject new waiters after dispatcher shutdown.
  A clean replacement becomes its own source only after successful acceptance.
  Foreground writes/truncates carry a separate mutation serial through unlocked
  IO and dirty marking. Invalidation and creation recheck that ownership after
  every drain, so a newly acknowledged write cannot be discarded as clean data.
  See vfscache/object_state.go, object_state_test.go, absence_dirty_test.go
  source_download_test.go and source_mutation_test.go.
  Observation conflicts retain syscall.EAGAIN on platforms that define it.
  Plan 9 uses a distinct error sentinel because its syscall package has no
  EAGAIN. The object_state_errno.go and object_state_plan9.go adapters belong
  to this local patch and are removed with it.

  Remote revalidation in open and writeback runs outside Item.mu. The request
  retains its original name, object/write generations and publication/dirty,
  descriptor and downloader state; changed ownership rejects the reply before
  absence handling or cache mutation. Pending lookups pin their cache lifetime
  while directory status checks proceed. Cache maintenance skips guarded items
  rather than requesting remote metadata while holding Cache.mu.
  See vfscache/metadata_lookup.go, metadata_lookup_test.go and
  metadata_latency_test.go. The latter covers normal asynchronous publication
  with deferred read-only/O_RDWR handles and the synchronous-close control.


  Linux full-cache kernel coherence requires negotiated FUSE_EXPLICIT_INVAL_DATA.
  Both mount drivers reject an unsupported negotiation before serving this mode.
  Explicit direct-I/O/writeback-cache options retain their existing I/O policy.
  The Linux full-cache mount adapters keep canonical inode wrappers and pin
  accepted file descriptors before acknowledging OPEN/CREATE. Local sparse
  writes publish their size and zero extents together; logical dirty mtime
  remains stable during range downloads. Retired File metadata uses its own
  retained Item, never a replacement at the same pathname. Failed truncation
  publishes only the accepted cache size.

  Explicit kernel data retirement separates local writes/upload metadata from
  externally accepted source changes. Kernel owners retain their notification
  obligations across descriptor close, cancelled opens and notification errors.
  A mount-owned queue retries failed retirement independently of new opens;
  foreign writes wait for affected views after releasing Item.mu. Writable
  kernel leases defer source replacement until pending mmap writes can finish.
  Clean disk-range reclamation preserves the accepted data generation and stays
  available to long-lived read-only descriptors. Native per-handle fsync uses
  the repository-local bazil module recorded in internal/thirdparty/bazil-fuse.
  Same-size/same-mtime replacement, cancelled opens, failed notification retry,
  foreign readers, readonly reclamation and rejected truncation have separate
  regression tests. Keep these when dropping the local override.

UPGRADE AND REMOVE
  When upgrading rclone, compare these copied packages against that release;
  UPSTREAM.json distinguishes original copies from the lifecycle patch.
  Keep local imports until an upstream release passes upload/listing, unlink
  and rename-overwrite regressions, including held read-only and grace handles.
  To drop the override after verification:
    1. Restore the upstream imports in cmd/all/all.go and backend/all/all.go.
    2. Restore upstream cmount imports in existing cmd/selfupdate code/tests.
    3. Remove only the copied paths listed by UPSTREAM.json, UPSTREAM.txt,
       UPSTREAM.json and COPYING.rclone. Remove the README's local VFS block
       and its links, then run go mod tidy to prune copied-test dependencies.
       Remove the testserver marker only if no remaining test relies on it.
    4. Run normal/cmount builds, SA tests and upstream VFS lifecycle regressions.
  Do not remove gclone's existing Drive, copy, selfupdate or version code.
  No build-preparation script or GitHub Actions workflow change is needed.

BUILD SCOPE
  This override applies to gclone CLI builds, including the Android CLI.
  The existing workflow's separate gomobile bind target explicitly builds
  upstream librclone/gomobile; that library keeps its upstream implementation.

LIMITS
  Cached bytes remain accessible on materialized old descriptors after unlink.
  Uncached ranges and deferred old opens fail rather than open a replacement.
  Crash/rollback leftovers in cache-dir/vfs-unlinked need manual recovery.
  The regression scope is unlink, late writeback and same-name replacement
  ownership. Application-specific database durability is outside this patch.
  Conflict revalidation relies on the backend's current-path NewObject view;
  it does not add universal backend linearizability or multi-host SQLite locks.
  Observation and source guards are per-Item memory state, not durable pathname
  tombstones. A new Item/process has the existing cache-reload semantics.

  Cached mount opens now prepare the backing lifetime before OS acknowledgement,
  preserving deferred mmap writes after unlink/overwrite without reconnecting old
  handles to a new pathname. Lazy non-mount VFS callers keep their original API.
  Linux mount publishes stable VFS inode numbers and one wrapper per node;
  lookup/create must share a kernel lock and page-cache identity. Its fsync
  callback now calls owned handle Sync and propagates local-cache errors.

  Dirty cache timestamps come from application metadata rather than physical
  cache writes/downloads. Local pwrite, zero-extent accounting and logical size
  publication share Item.mu; bookkeeping completes before cancellation can
  release that lock. Empty or failed writes do not create phantom zero extents.
  Keep modtime_lifetime_test.go, sparse_write_stat_test.go, mountlib/handle_test.go
  and mount/{inode_lifetime,open_sync}_test.go when removing these fixes.

LOCK LATENCY OVERRIDE
  Cache.mu protects short ownership/map transactions. Item-lock waits, cold
  metadata loading, cleaner reset/drain, accounting scans and staged-file cleanup
  execute outside it. Per-name maintenance also fences captured Item pointers;
  deferred open validates ownership before creating or saving cache paths, and
  VFS reacquires an evicted binding without exposing a new EBUSY policy.

  Directory refreshes fetch and prepare entries without retaining namespace
  locks. Still-valid positive snapshots remain usable during a forced refresh;
  expired/invalidated/unknown names and strict readdir retain strict refresh
  semantics. Per-file publication fences and per-name local mutation stamps
  survive unlocked fetches. Parent/root generations reject obsolete tree replies.
  Namespace helpers release parent locks before waiting on File/child locks;
  rename replacement still publishes retirement and replacement atomically.

  The publication_open regression uses an explicit directory scheduling gate
  because entry preparation now occurs unlocked. Its accepted-ID, subsequent
  upload and exact-byte assertions are retained.

  Drive's independent resolver is documented in internal/dircache/UPSTREAM.txt.
  SA rotation still serializes account selection/building, while ordinary readers
  use an atomically published complete client tuple. Credentials and v1/v2 clients
  are built privately; failed construction cannot expose a partial replacement.

  Drop these changes only after equivalent upstream behavior passes latency
  gates as well as the existing lifetime/data regressions. Data-only success is
  not latency acceptance. Same-file coherence waits and Linux parent-directory
  serialization remain part of the filesystem contract.
